## Часть 1: Сравнительный анализ моделей доступа

### Задание 1.1. Анализ сценариев

---

#### Сценарий А: Стартап с 5 сотрудниками

| Параметр | Ответ |
|----------|-------|
| **Какая модель доступа подходит?** | DAC (дискреционная) |
| **Почему?** | Мало сотрудников, все друг другу доверяют, важна скорость работы, а не строгая безопасность |
| **Плюсы** | Простота, гибкость, не нужен администратор безопасности |
| **Минусы** | При росте компании станет неудобно — придётся менять модель |
| **Что изменится при масштабировании?** | При 20+ сотрудниках DAC станет неудобной, придётся переходить на RBAC |

---

#### Сценарий Б: Военное ведомство

| Параметр | Ответ |
|----------|-------|
| **Какая модель доступа подходит?** | MAC (мандатная) |
| **Почему?** | Требуется строгая иерархия уровней секретности, запрет на утечку информации |
| **Как реализовать "No Read Up" и "No Write Down"?** | Присвоить каждому пользователю и документу уровень доступа (Открыто/Секретно/Совершенно секретно). Система сама не даст читать выше своего уровня и записывать ниже |
| **Дополнительные меры** | Аудит всех действий, шифрование, физическая изоляция серверов |

---

#### Сценарий В: Корпорация с 500 сотрудниками

| Параметр | Ответ |
|----------|-------|
| **Какая модель доступа подходит?** | RBAC (ролевая) |
| **Почему?** | Легко управлять правами, роли соответствуют должностям, есть иерархия |
| **Как отразить организационную структуру?** | Создать роли: "Сотрудник", "Менеджер отдела", "Директор". Менеджер наследует права сотрудника, директор — права менеджера |
| **Как реализовать разделение обязанностей (SoD)?** | Например, запретить одному пользователю быть одновременно "Бухгалтером" и "Аудитором" |

### Вывод по Части 1

На основе анализа можно сделать следующие выводы:

1. **DAC** подходит для малых проектов с доверенной средой, но не масштабируется
2. **MAC** обязательна для государственных и военных структур, но сложна в администрировании
3. **RBAC** — оптимальный выбор для большинства коммерческих организаций, так как сочетает безопасность и удобство управления

Для учебного проекта "Система управления задачами" выбрана модель **RBAC**, так как она:
- Позволяет гибко управлять правами через роли
- Легко масштабируется при росте количества пользователей
- Соответствует принципу минимальных привилегий
